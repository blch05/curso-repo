Cómo leer documentación y ser autodidacta

Saber programar no es memorizar todas las etiquetas y propiedades de memoria. Es saber buscar, leer documentación oficial y probar hasta entender qué hace cada línea.

Lo que nos vamos a llevar hoy

  • Cómo navegar MDN Web Docs sin marearte.
  • Cómo googlear y el método "romper para entender".
  • Comandos básicos de terminal para moverte sin miedo.

Tu misión al terminar

  • Investigar 6 propiedades/etiquetas en MDN.
  • Escribir tu propia mini-guía en apuntes.md.
  • Entregarla abriendo un Pull Request.
El hábito clave

La trampa de copiar y pegar

Copiar un ejemplo sin entenderlo te ahorra 2 minutos hoy, pero te frena 2 horas mañana cuando necesitás cambiar algo y no sabés qué tocar.

Copiar a ciegas

  • Pegás el bloque entero del ejemplo esperando que ande.
  • Si se rompe el diseño, empezás a probar cosas al azar.
  • En el siguiente proyecto no sabés por dónde arrancar.

Leer, romper y entender

  • Leés qué hace la propiedad y qué valores acepta.
  • Cambiás 2 valores a propósito para ver qué pasa.
  • Podés explicarlo con tus palabras y adaptarlo a cualquier caso.
Mapa de MDN

La documentación no se lee como un libro

Cuando abrís una página de MDN Web Docs, no leas todo de arriba a abajo. Andá directo a estas 4 zonas en orden:

1

Descripción corta

Las primeras 2 líneas te confirman si esa es la propiedad que estás buscando.

2

Ejemplo interactivo (Try it)

Tocá los botones y cambiá valores ahí mismo. Es la forma más rápida de verlo en acción.

3

Sintaxis y valores

Mirá qué unidades o palabras clave acepta (ej. px, %, center).

4

Qué saltear al principio

Ignorá especificaciones W3C y tablas históricas de navegadores viejos.

Usá siempre la fórmula: tecnología + qué querés lograr + mdn. En inglés suele haber más resultados, pero MDN tiene gran parte traducida al español.

Terminal básica

Supervivencia en la Terminal

La terminal no muerde: es lo mismo que el explorador de carpetas de Windows/Mac, pero con texto. Estos 6 comandos te resuelven el 90% del día a día:

Navegar y crear carpetas

  • pwd — muestra en qué carpeta estás parado.
  • ls — lista los archivos y carpetas de ese lugar.
  • cd carpeta — entra a una carpeta (cd .. sube un nivel).
  • mkdir nombre — crea una carpeta nueva.
  • clear — limpia la pantalla cuando hay mucho texto.

Atajos y error #1

  • Tab: autocompleta nombres de carpetas y archivos (evitá tipear todo a mano).
  • Flechas ↑ / ↓: recuperan comandos que ya escribiste.
  • Ctrl + C: frena un comando que se quedó colgado.
  • Error #1: correr git o node parado en la carpeta equivocada. Chequeá siempre con pwd y ls.
Consigna práctica

Armá tu propia documentación

Creá entregas/<tu-usuario>/clase-00-documentacion/apuntes.md y documentá al menos 6 temas investigados en MDN:

Qué temas incluir

  • 3 temas que ya usamos: width en %, flex-direction, justify-content, align-items, selectores (a img vs .clase).
  • 3 propiedades nuevas: buscadas desde cero en MDN (ej. border-radius, box-shadow, opacity, cursor, :hover, gap).

Cada ficha debe tener

  • Enlace oficial a MDN.
  • Explicación con tus palabras (sin copiar).
  • 2 o 3 valores principales.
  • Un ejemplo propio + qué probaste o descubriste.
Entrega en GitHub

Subilo como Pull Request

Recordá trabajar solo dentro de tu carpeta para que el check automático evaluar-pr quede en verde. 

# 1. Chequeá que estás en curso-repo, actualizá y creá la rama
pwd
git checkout main
git pull origin main
git checkout -b entrega/clase-00-documentacion

# 2. Creá tu carpeta desde la terminal y armá apuntes.md adentro
mkdir entregas/<tu-usuario>/clase-00-documentacion

# 3. Guardá y subí tus cambios
git add .
git commit -m "docs: apuntes de lectura de documentacion"
git push origin entrega/clase-00-documentacion

Después entrá a tu fork en GitHub → Compare & pull request → completá la plantilla (declaración honesta de IA incluida).
